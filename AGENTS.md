# Laranex Schema Viewer UI

Independent npm package `laranex-schema-viewer-ui`: the unified `laranex-schema` contract and the shared, framework-independent ERD viewer for Laravel, Python and Node.js. It ships the contract artifacts (`contract/`), a React component, and a standalone static bundle (`dist/viewer/`) that hosts serve without Node at runtime. It never extracts ORM metadata, touches a database, contains CLI or MCP code, or reads framework-specific formats: producers convert their own legacy snapshots.

## Architecture

- `docs/contract.md`: the normative contract. Read it before changing anything in `src/contract/` or `contract/`.
- `src/contract/`: `types.ts`, `document.ts` (shapes that generate both `contract/schema.json` and the runtime checks), `validate.ts` (strict and lenient validation, reference rules), `graph.ts` (the shared link builder), `comparison.ts`, `migration.ts` and `inference.ts` (shared producer algorithms with conformance cases; the viewer never calls them), `ids.ts` (rule-based ids), `gate.ts` (the CI gate: `gateDocument` and the separate gate report; viewers never call it), `serialize.ts` and `sha256.ts` (canonical bytes, revisions, ids), `viewer-config.ts` (host settings beside the document).
- `contract/`: distributed artifacts, all generated by `npm run contract` from `tests/fixtures/*.ts`: `schema.json`, `gate-report.schema.json`, valid, invalid and gate fixtures, graph, comparison, migration, inference and gate conformance cases; plus `check.mjs` for producers' CI.
- `src/export/`: the client-side exporters (`laranex-schema-viewer-ui/export`, `docs/exports.md`): pure, deterministic Mermaid, DBML, Markdown and scoped-JSON conversions with warnings for what a format cannot state; no React, no DOM. Golden outputs live in `tests/fixtures/export/` (`UPDATE_EXPORTS=1 npx vitest run tests/export.test.ts` rewrites them; review every change).
- `src/viewer/`: the React viewer. `graph.ts` (pure functions over the stored links), `layout.ts` (ELK, loaded lazily and run on the page, CSP-safe), `routing.ts` (orthogonal edges), `SchemaViewer.tsx`, `TableNode.tsx`, `SchemaEdge.tsx`, `Details.tsx`, `DownloadDialog.tsx`, `exportImage.ts` (SVG and PNG from one list of shapes), `offline.ts` (the self-contained HTML export), `icons.tsx` (the one icon registry, `Icon` re-exported from `ui.tsx`), `brand.ts` (the brand mark, the favicon's SVG, data URI and pixels; the Vite build writes `favicon.svg` and `favicon.ico` from it with `scripts/ico.ts`), `theme.ts` and `styles.css` (scoped to `.lsv`).
- `src/standalone/`: the static bundle's bootstrap: reads the document (or a `ViewerConfig`) from `script#schema-viewer-data`, `window.__SCHEMA_VIEWER__`, or `data-snapshot-url`, and defines `<laranex-schema-viewer src>`. `vite.offline.config.ts` builds the same entry as one script with ELK inlined; `scripts/viewer-html.mjs` moves it to `dist/viewer/offline.js` and writes `dist/viewer/index.html` and `manifest.json`.
- `dev/`: the development page (`npm run dev`, http://127.0.0.1:5181/dev/index.html) with every valid fixture and a generated 200-table schema.
- `e2e/`: Playwright tests of the built bundle, served by `e2e/server.mjs` with the Python package's Content-Security-Policy.

## Conventions

- The visual design and interaction model follow the Python viewer; layout and routing follow the Laravel viewer. Icons, the brand mark and the favicon come from the Laravel viewer, drawn in this package's theme tokens (never Laravel's palette, never color literals in icons). Keep attribution in `NOTICE`.
- Keep foreign-key constraints and ORM relationships separate everywhere: contract, graph, edges, legend, details and exports. No exporter turns a relationship, a relationship-only link or an inferred association into a foreign key, and none invents a default, constraint or index.
- Render schema strings as text only: no `dangerouslySetInnerHTML`, no HTML built from schema data.
- The bundle must work under `script-src 'self'` with no CDNs or runtime network access beyond the snapshot URL a host gives it and its own files (`offline.js`, `app.css`, fonts and favicon, fetched same-origin only to build an offline page or embed fonts in an SVG).
- Changing the contract means updating `docs/contract.md`, `types.ts`, `document.ts`, `validate.ts`, the fixtures (`npm run contract`) and the changelog together. Additive changes bump the minor version; anything else the major. No framework adapters or format detection in this package.
- TypeScript strict mode; pinned dependency versions; no unrelated refactoring.

## Development and validation

```bash
npm install
npm run typecheck
npm test                 # unit and component tests (Vitest, jsdom)
npm run build            # dist/lib, dist/types, dist/viewer (+ index.html, manifest.json)
npm run test:browser     # Playwright on the built viewer (npx playwright install chromium webkit first); PORT=… picks another port
                         # e2e/visual.spec.ts screenshots compare with macOS Chromium baselines (--update-snapshots after an intended change)
npm run test:package     # npm pack, install into a temporary project, check exports, artifacts and the manifest
npm run contract         # regenerate contract/ after changing tests/fixtures/*.ts or the shapes
npm run contract:check   # check.mjs over the valid fixtures
```

Run focused tests first, then `npm run check`. Report skipped or unavailable browsers accurately.

## Documentation site

Markdown lives in `docs/`; VitePress config, theme and Node deps live in `.gh-page/` (`srcDir: ../docs`, base `/schema-viewer-ui/`). The live demo is the built bundle (`dist/viewer`) loading the synthetic contract fixtures. Build the package first, then in `.gh-page/`: `npm ci`, `npm run dev`, `npm run check`. `deploy-docs.yml` deploys `main` to https://laranex.github.io/schema-viewer-ui/.

## Releases

Record user-visible changes under `## [Unreleased]` in `CHANGELOG.md`. Publishing a GitHub release `vX.Y.Z` runs `.github/workflows/publish.yml`: the full test workflow, a tag/version match, a check that the version is not on npm, then npm Trusted Publishing. Do not bypass these gates.

## Safety

- Fixtures are synthetic; never add a real application's snapshot.
- Do not create commits, tags, pushes, releases or publishes without explicit authorization. Never weaken tests or security checks to pass.
- The sibling Laravel and Python repositories are read-only references.
